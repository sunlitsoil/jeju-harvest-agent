# 결과 설명자료 (v0.3.3, 2026-11-08)

결과 파일은 모두 `eval/results/`에 모델 이름·실행 시각과 함께 있다. 허브 자료는 2026-11-07까지 수록된 것을 2026-11-08에 조회했다.

## 1. 계획기 평가

질문을 읽고 품종과 의도(지금 시세·출하 시기·시장 비교·전망)를 맞혔는지 센다. 개발 20문항은 개발 중에도 썼다. 보류 묶음은 실행 전에 질문과 정답을 커밋하고 한 번만 돌렸다(보류1 `57c4948`, 보류2 `6ef8b63`, 보류3 `e322df7`). 목록 밖 질문(각 묶음 6·3·3개)은 작물을 다시 물으면 정답이다.

| 계획기 | 모델 | 보류1 의도 전체(목록 안) | 보류2 | 보류3 |
|---|---|---|---|---|
| `rule` | 없음 | 22/30 (16/24) | 9/15 (6/12) | 8/15 (5/12) |
| `llm` | gemma4 31B (Ollama Cloud) | 27/30 (21/24) | 12/15 (9/12) | 15/15 (12/12) |
| `auto` | qwen3.5 4B 생각 켬 | 23/30 (17/24) | 9/15 (6/12) | — |
| `auto` | qwen3.5 4B 생각 끔 | — | 8/15 (6/12) | 8/15 (5/12) |

규칙에 표현을 더해도 새 질문에서는 나아지지 않았고(보류3 목록 안 5/12), 큰 모델은 세 묶음 합계 목록 안 42/48이었다. 그래서 외부 API를 쓸 수 있으면 `llm` 모드를 권장하고, 없으면 `rule` 모드에 다음 질문 버튼으로 보완한다.

파일: `planner-*.json`(개발 20), `holdout-*.json`, `holdout2-*.json`, `holdout3-*.json`

## 2. 핵심 문장 고르기 평가

LLM은 답변 문장의 번호만 고른다. 번호가 아닌 답, 범위 밖 번호는 버린다. 보류1 30문항 결과다.

| 모델 | 채택 | 폐기 | 비고 |
|---|---|---|---|
| gemma4 31B | 22 | 1 | 7건은 고르지 않음 |
| qwen3.5 4B 생각 끔(전망 문장 고정 전) | 24 | 0 | 전망 질문 3건에서 시세 문장을 고름 |
| qwen3.5 4B 생각 끔(전망 문장 고정 후, v0.3.3) | 23 | 1 | 전망 결과 문장은 규칙으로 고정 |

파일: `pick-holdout-*.json`

## 3. 허브 전망 실음 여부

전망을 주는 9품종에 대해 비교 기준 배수(마지막 실제 가격·전국 평균 대비)를 2·3·5배로 바꿔 실리는 품종 수를 셌다. 6·6·7종이 실렸고 기본값은 3배다. 흙당근 등은 그 시장 가격이 전국 평균과 크게 달라 싣지 않는다.

파일: `forecast-coverage-2026-11-08.json`

## 4. 재현

```bash
python3 -m unittest discover -s tests -v                       # 단위 테스트 28개, 인터넷 없이
EVAL_QS=holdout3_questions.json python3 eval/eval_planner.py   # 계획기 평가(LLM 환경변수를 주면 LLM 계획기도)
python3 eval/forecast_coverage.py                               # 전망 9종 실음 집계
```

단위 테스트는 저장 응답만 써서 언제나 같다. 실제 조회는 허브가 새 자료를 올리면 숫자가 바뀐다. LLM 평가는 모델·서버 버전에 따라 달라질 수 있다.
